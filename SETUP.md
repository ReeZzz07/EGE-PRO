# Подключение бэкенда (Supabase + настоящая LLM)

Без этих шагов приложение полностью работает в **гостевом/офлайн-режиме**: аккаунты — локальные (в `localStorage` этого браузера), а ИИ-репетитор отвечает через упрощённый офлайн-фолбэк (`src/data/tutor.ts`), а не настоящую модель. Это сделано намеренно, чтобы приложение можно было открыть и потрогать сразу, без бэкенда.

Чтобы включить настоящие аккаунты, синхронизацию прогресса между устройствами и проверку по критериям через настоящую LLM — выполни шаги ниже.

## 1. Создай проект Supabase

1. Зайди на [supabase.com](https://supabase.com) → New Project.
2. Дождись инициализации проекта.
3. В `Project Settings → API` скопируй `Project URL` и `anon public` ключ.

## 2. Заполни `.env`

```bash
cp .env.example .env
```

Впиши в `.env`:

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

Перезапусти `npm run dev` — приложение автоматически переключится с гостевого режима на Supabase (это определяет `src/lib/supabase.ts` по наличию этих двух переменных).

## 3. Примени миграцию БД

Через Supabase CLI (рекомендуется):

```bash
npm install -g supabase
supabase login
supabase link --project-ref xxxxx   # xxxxx — из URL проекта
supabase db push
```

Миграция лежит в [supabase/migrations/0001_init.sql](supabase/migrations/0001_init.sql) — таблицы `profiles`, `attempts`, `diagnostics`, `study_plans`, `essay_submissions`, `essay_assessments`, `ai_messages`, `hints_used`, все с RLS-политиками «только владелец строки», плюс триггер, который создаёт профиль автоматически при регистрации.

Либо вставь содержимое файла вручную в `SQL Editor` в дашборде Supabase и выполни.

## 4. Задеплой Edge Function `ai-tutor`

```bash
supabase functions deploy ai-tutor
```

Функция лежит в [supabase/functions/ai-tutor](supabase/functions/ai-tutor) — это единая точка входа для ИИ-репетитора: объяснение темы, уровневые подсказки, проверка сочинений/развёрнутых ответов по критериям. Системный промпт и политика (что можно и нельзя ИИ) — в `prompt.ts`.

## 5. Добавь ключ Anthropic (настоящая LLM)

Нужен платный API-ключ Anthropic (console.anthropic.com):

```bash
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
```

Без этого секрета `ai-tutor` вернёт ошибку, и клиент автоматически откатится в офлайн-режим (см. `src/lib/aiTutor.ts` → `callAiTutor`), так что приложение не сломается, просто ИИ будет попроще.

## 6. Проверка

- Зарегистрируйся на лендинге → должен появиться реальный пользователь в `Authentication → Users` в дашборде Supabase.
- Реши пару заданий → строки должны появиться в таблице `attempts`.
- Открой сочинение (например, задание «Сочинение-рассуждение по тексту», предмет «Русский язык») и отправь на проверку → в `essay_submissions`/`essay_assessments` появятся записи, а оценка в интерфейсе будет содержательной (не «офлайн-заглушка»).
- В чате репетитора текст ответа будет исходить от настоящей модели — сообщения логируются в `ai_messages` (аудит, раздел 14.4 ТЗ).

## Что дальше сознательно не реализовано (см. итоговый отчёт)

Роли учитель/родитель/админ, классы, интервальное повторение, генерация заданий ИИ, векторная БД/семантический поиск, платежи, нативные мобильные приложения, self-hosted инфраструктура (Docker/K8s/Redis/MinIO/Prometheus/Sentry) — см. `.docs/TZ.md` для полного видения и раздел 18.3 «что можно отложить».
