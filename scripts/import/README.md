# Импорт банка заданий ФИПИ (`output/`)

Конвейер решает задания из `output/<subject>/tasks.jsonl` через LLM (два независимых
решения → сравнение → арбитраж при расхождении) и пишет результат в
`output/<subject>/tasks.answered.jsonl`. Для заданий с развёрнутым ответом (`full`,
«Развёрнутый альтернативный») единственно верного ответа нет — вместо этого генерируются
критерии оценивания, и такие задания **всегда** уходят на проверку методиста.

Задания, где в самом `output/` физически нет списка вариантов ответа (ни в поле `variants`,
ни в HTML) — скрипт такие не решает, сразу помечает `missing_options_in_source` и на проверку.
Это дефект исходных данных, не провайдера — сменой LLM не чинится.

## Провайдер: Anthropic (по умолчанию) или Qwen

Переключается через `SOLVER_PROVIDER` (см. `lib/provider.mjs`). Логика конвейера одна и та же —
меняется только то, куда уходят запросы.

| | Anthropic | Qwen (Alibaba Cloud DashScope) |
|---|---|---|
| Переменная окружения с ключом | `ANTHROPIC_API_KEY` | `DASHSCOPE_API_KEY` |
| Модели | `claude-sonnet-5` (задаётся `SOLVER_MODEL`) | `qwen-max` для текста / `qwen-vl-max` для заданий с картинками (дешевле — используется только там, где реально нужна картинка) |
| Ключ получить | console.anthropic.com | Alibaba Cloud Model Studio (bailian/DashScope) |
| Точность на STEM+картинках | выше | ниже — обязательно проверяй калибровкой, риск ошибок больше |

Для Qwen эндпоинт по умолчанию международный (`dashscope-intl.aliyuncs.com`) — если у тебя
аккаунт в материковом Китае, переопредели `DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`.

**Важно:** у vision-модели (`qwen-vl-max`) форсированный `tool_choice` (то, на чём держится весь
парсинг структурированного ответа) исторически поддерживается менее стабильно, чем у Anthropic.
Калибровка обязательна перед полным прогоном ещё сильнее, чем обычно — если модель не сможет
вызвать tool, увидишь ошибку прямо в `tasks.answered.jsonl` (`status: "error"`).

## 1. Калибровка (сначала обязательно)

```bash
# Anthropic
export ANTHROPIC_API_KEY=sk-ant-...
node scripts/import/solve-tasks.mjs --limit=3

# Qwen
export SOLVER_PROVIDER=qwen
export DASHSCOPE_API_KEY=sk-...
node scripts/import/solve-tasks.mjs --limit=3
```

`--limit=3` — по 3 первых необработанных задания на предмет (~33 задания на 11 предметов),
достаточно, чтобы увидеть разнообразие типов и посчитать реальную стоимость.

Прогресс пишется построчно в `output/<subject>/tasks.answered.jsonl` — скрипт можно прерывать
(Ctrl+C) и перезапускать: уже решённые `task_id` не трогаются повторно.

## 2. Проверка результата глазами

```bash
node scripts/import/review.mjs
# только то, что помечено на ручную проверку:
node scripts/import/review.mjs --only-review
```

Покажет условие рядом с ответом/критериями по каждому заданию — так удобно сверить с
реальным знанием предмета, что модель не ошиблась.

## 3. Полный прогон

Когда калибровка устраивает по качеству и цене:

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # или SOLVER_PROVIDER=qwen + DASHSCOPE_API_KEY=...
node scripts/import/solve-tasks.mjs --concurrency=6
```

Без `--subjects=` и `--limit=` — берёт всё, что ещё не решено, по всем 11 предметам.
В консоли в конце — суммарное число вызовов API и токенов (сумма $ считается по своей
модели/тарифу — сверяй с https://www.anthropic.com/pricing или https://www.alibabacloud.com/help/en/model-studio/models — цены отличаются в разы).

Полезные флаги:
- `--dry-run` — только посчитать объём (auto/essay/пропуски), без единого вызова API.
- `--subjects=biologiya,fizika` — ограничить предметами.
- `--concurrency=N` — параллельность (по умолчанию 4).

## Что дальше (после решения) — не входит в этот скрипт

1. Задания с `needs_review: true` (расхождение решений, ошибки, критерии сочинений,
   444 задания информатики с zip/txt-датасетами) — ручная проверка методиста обязательна.
2. Отдельный шаг **публикации**: перенос `tasks.jsonl` + `tasks.answered.jsonl` + файлов из
   `assets/` в таблицы Supabase (`tasks`, `task_media`, `task_answers`/`task_criteria`) и
   Supabase Storage — этот шаг ещё не написан, разумно делать его после того, как решённые
   данные пройдут проверку и станет ясно, сколько заданий реально дошло до публикации.
